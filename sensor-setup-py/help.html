1. 시작하기 전에

순서가 중요합니다

① 보드 진단  →  ② 펌웨어 굽기  →  ③ 설정 주입  →  ④ 데이터 수집
  입고 검사        ─── 이 설명서 ───        SHT 진동센서 수집
보드 진단(입고 검사)은 이 패키지에 들어 있지 않습니다. 출하 전에 제조·배포 담당자가 boardcheck 로 검사한 보드를 받는 것이 원칙입니다. 진단을 거치지 않은 보드에서 ① 이 "센서 미감지" 로 멈추면 하드웨어 문제이므로 배포 담당자에게 보드 점검을 요청하십시오. 펌웨어를 다시 구워도 해결되지 않습니다.

실행 — 명령은 하나입니다

받은 iis3dwb-setup-<버전>.tar.gz 를 풀고, 그 폴더에서 터미널로 bash run.sh 를 실행합니다. 설치 단계가 따로 없습니다.

tar -xzf iis3dwb-setup-<버전>.tar.gz
cd iis3dwb-setup-<버전>
bash run.sh
언제run.sh 가 하는 일
처음 실행 환경을 점검하고, 빠진 USB 포트 권한(udev 규칙·사용자 그룹)을 설정한 뒤 창을 띄웁니다. 이때 관리자 비밀번호를 물을 수 있습니다. 재로그인은 필요 없습니다. 바탕화면에 SHT 진동센서 설정 아이콘도 만듭니다.
두 번째부터 점검만 하고 바로 창을 띄웁니다. 비밀번호를 묻지 않습니다. 바탕화면 아이콘을 더블클릭해도 됩니다 (“실행할까요?” 를 묻는 창이 뜨면 실행).
./run.sh 가 아니라 bash run.sh 로 실행하세요. USB 메모리(FAT 포맷)를 거쳐 복사하면 실행권한이 사라져 ./run.sh 는 “허가 거부” 가 납니다. bash run.sh 는 권한과 상관없이 동작합니다.

새 버전으로 바꿀 때: 새 tar.gz 를 옆 폴더에 풀고 그 폴더에서 bash run.sh 를 한 번 실행하면 끝입니다. 입력해 둔 값은 버전과 상관없이 그대로 남고, 바탕화면 아이콘은 마지막으로 실행한 폴더를 가리키도록 바뀝니다. 문제가 있으면 예전 폴더에서 실행해 되돌아가면 됩니다.

SSH 로 접속해 쓰는 경우: 처음 실행에서 권한을 설정한 뒤 한 번 로그아웃했다가 다시 접속해야 적용됩니다. 화면(데스크톱)에서 쓸 때는 필요 없습니다. 아무것도 바꾸지 않고 점검만 하려면 bash install.sh --check.

이 설명서는 화면 왼쪽 아래 도움말 버튼으로 언제든 다시 열 수 있습니다 (python3 helpdoc.py 로도 열립니다).

인터넷(폐쇄망)과 ESP-IDF 는 필요 없습니다. 구울 펌웨어는 패키지의 firmware/ 에, 굽는 도구(esptool)와 시리얼 라이브러리(pyserial)는 vendor/ 에 들어 있습니다. OS 쪽에 필요한 것은 Python 3.7 이상과 tkinter 뿐이며, 둘 다 Raspberry Pi OS Desktop 이미지에 기본으로 들어 있습니다.

화면 맨 위가 빨간 글씨라면 진행하지 마세요. 번들 펌웨어 없음 — ① 펌웨어 굽기 사용 불가 가 보이면 패키지가 온전하지 않습니다. 배포 담당자에게 정상 패키지를 요청하십시오. 정상이면 패키지 1.0.0 · 굽기 직전 무결성을 확인합니다 처럼 (숫자는 받은 패키지 버전) 초록 글씨가 보입니다.

2. 화면 읽는 법

진동센서 목록 — 어느 보드에 작업하는지

┌ 진동센서 목록 ──────────────────────────────────────────┐
│ [MAC 주소 확인] [목록만 갱신]                             │
│  USB 포트     장치      MAC                 이력         │
│  usb-0:1.1  ttyACM1  9c:13:9e:90:a9:f0    대기    ←선택 │
│  usb-0:1.2  ttyACM0  9c:13:9e:84:d5:50    완료 16:02    │
│                                                          │
│ 대상: 9c:13:9e:90:a9:f0  (ttyACM1 · usb-0:1.1)           │
│ 이 보드에 대한 작업 이력이 없습니다 (새 보드).             │
└──────────────────────────────────────────────────────────┘
항목뜻
USB 포트 보드가 꽂힌 구멍. 재부팅·재연결에도 변하지 않습니다.
장치 ttyACM0 같은 번호. 꽂는 순서에 따라 바뀝니다 — 이것으로 보드를 구분하지 마세요.
MAC 보드를 구분하는 유일한 값. MAC 주소 확인 을 누르거나 ② 설정 주입 을 하면 채워집니다. 아직이면 미확인.
이력 이 보드에 직전에 넣은 설정. 처음이면 대기.
왜 MAC 을 따로 읽어야 하나요? 이 보드의 USB 브리지칩에는 고유 일련번호가 없습니다. 두 대를 꽂아도 시스템에는 같은 이름으로 보여 포트 번호만으로는 어느 보드인지 알 수 없습니다. MAC 은 보드마다 다르고 읽을 수 있는 유일한 식별자입니다.

두 버튼의 차이

버튼하는 일걸리는 시간
MAC 주소 확인 모든 포트의 MAC 을 읽습니다. 보드가 리셋됩니다. 포트당 약 3초
목록만 갱신 연결 상태만 다시 봅니다. 보드를 건드리지 않습니다. 즉시

작업 버튼

버튼하는 일
현재 설정 읽기 선택한 보드에 저장된 값을 아래 입력란에 채웁니다. 없는 값은 비워 둡니다 — 이미 입력한 내용을 지우지 않습니다. 다른 PC 에서 설정한 보드처럼 이력이 없는 보드의 설정을 알아낼 때, 설정 일부만 바꿔 다시 넣을 때 씁니다.
① 펌웨어 굽기 펌웨어를 씁니다. 약 1~2분. 저장된 설정(NVS)은 지워지지 않습니다.
② 설정 주입 입력값을 보드에 넣고, 보드가 되울린 값을 입력값과 대조합니다.
취소진행 중인 단계를 중단합니다

3. 센서 1대 — 기본 절차

1단계 — 보드를 꽂고 확인

MAC 주소 확인 을 누릅니다. 목록에 MAC 이 채워지고, 그 보드가 자동으로 선택됩니다.

보드는 한 대씩 차례로 읽습니다 (한 대에 약 3초). 읽는 동안 목록의 MAC 칸에 진행 상황이 나오고 아래 막대가 움직입니다.

MAC 칸뜻
대기 — 다음 차례앞 보드를 읽는 중. 곧 차례가 옵니다 (문제 아님)
확인 중…지금 이 보드를 읽고 있습니다
USB 복구 중…USB 통신이 멈춰 있어 도구가 자동으로 복구한 뒤 다시 읽습니다 (몇 초 더 걸림)
9c:13:…완료

MAC 이 읽기 실패 로 나오면 7장을 보세요.

2단계 — 설정 입력

데이터 전송 방식을 먼저 고릅니다. 이 선택이 나머지를 결정합니다.

  • USB 직결 (시리얼) — 케이블로 연결된 PC 가 받습니다. WiFi 입력란이 회색으로 잠깁니다 (값은 지워지지 않습니다).
  • WiFi (UDP) — SSID·비밀번호·라즈베리파이 IP·수신 포트를 입력합니다.

이어서 측정 설정(속도·읽기 방식·범위)을 정합니다 → 5장

3단계 — ① 펌웨어 굽기

확인 대화상자에서 예를 누릅니다. 약 1~2분 걸립니다.

진행 중 USB 케이블을 뽑지 마세요. 펌웨어가 반쯤 써진 상태가 되면 보드가 부팅하지 못합니다 (다시 구우면 복구됩니다).

끝나면 로그에 ✅ 펌웨어 쓰기 완료 (이미지 3개 검증 3회) 가 나오고, 이어서 부팅 로그를 읽어 판정합니다.

새 보드는 아직 설정이 없으므로 이 단계에서는 자격증명 출처: Kconfig 폴백 (NVS 미설정), 스트리밍: 미시작 으로 나오는 것이 정상입니다. ② 설정 주입 후에 시작됩니다.

4단계 — ② 설정 주입

주입 후 보드가 되울린 설정을 입력값과 대조합니다. 이것이 핵심입니다 — "저장은 했지만 반영되지 않은" 상태를 걸러냅니다.

로그에서 이런 줄을 확인하십시오.

펌웨어가 읽은 설정: 서버 192.168.0.77:9000, rate=4, transport=2, fs=±4g
스트리밍: 시작됨 ✅

USB 직결이면 WiFi: skipped_serial_mode · 자격증명 출처: 확인 불가 가 함께 나오는데, WiFi 를 쓰지 않으므로 정상입니다.

4. 센서 2대 — 순차 절차

두 대를 함께 꽂아도 됩니다. 다만 작업은 한 대씩 차례로 합니다. 도구가 그렇게 강제합니다 — 굽는 동안 대상 선택이 잠깁니다.

왜 동시에 하지 않나요

  • 플래시 도구는 포트를 독점합니다. 동시 실행은 서로의 보드 리셋에 영향을 줍니다.
  • USB 통신이 멈춰 복구할 때 포트 번호가 재배치됩니다. 동시 진행 중이면 다른 보드의 경로가 바뀌어, 엉뚱한 보드에 쓸 수 있습니다.
  • 동시에 해서 얻는 시간은 몇 분뿐입니다.

절차

  1. 두 보드를 모두 꽂습니다.
  2. MAC 주소 확인 — 목록에 MAC 두 개가 나옵니다. 어느 MAC 이 어느 구멍인지 적어 두세요.
  3. 1번(위쪽 줄) 보드를 클릭해 선택합니다. 아래 안내문에 대상: 9c:13:… 가 맞는지 확인합니다.
  4. 설정을 입력하고 ① 펌웨어 굽기 → 끝나면 ② 설정 주입. 진행 중에는 다른 보드를 고를 수 없습니다 (한 번에 한 대만).
  5. 2번 보드를 클릭해 선택하고 ① → ② 를 반복합니다. 설정은 입력란에 그대로 남아 있으니 다시 입력할 필요가 없습니다.
  6. 끝나면 목록의 이력 칸에 두 보드 모두 완료 HH:MM 이 표시됩니다.
WiFi(UDP) 로 두 대를 쓸 때는 수신 포트를 서로 다르게 입력하십시오. 두 센서가 같은 IP·같은 포트로 보내면 수신기가 두 데이터를 한 파일에 섞고, 유실이 실제보다 훨씬 크게 잡힙니다.
센서라즈베리파이 IP수신 포트
첫 번째192.168.0.779000
두 번째192.168.0.779001

받는 쪽 SHT 진동센서 수집에서는 그 센서 칸의 수신을 WiFi 로 바꾸고 같은 포트를 입력합니다.

USB 직결(transport=2)에서는 포트가 쓰이지 않으므로 신경 쓸 필요가 없습니다.

설정은 보드에 붙고, 센서 번호는 USB 구멍에 붙습니다. 주입한 설정은 보드를 따라가지만, 수집기가 부르는 센서 1 / 센서 2 는 꽂힌 구멍이 정합니다. 현장에서 다른 구멍에 꽂으면 번호가 달라집니다. 센서를 교체할 때는 같은 구멍에 꽂으십시오.

5. 설정 항목 설명

데이터 전송 방식

선택쓰는 경우받는 방법
USB 직결 (시리얼) WiFi 가 없거나 불안정한 현장. 최대 26.6 kHz. SHT 진동센서 수집의 bash run.sh
WiFi (UDP) 케이블 없이 떨어진 곳에 둘 때 SHT 진동센서 수집에서 그 센서의 수신을 WiFi 로

둘은 배타 선택입니다. USB 직결을 고르면 보드는 WiFi 에 접속하지 않습니다.

측정 속도

기본은 1 kHz 입니다. 데이터량을 가장 적게 하기 위한 값이며, 목적에 맞게 현장에서 고르십시오. 1분·1대 CSV 기준 대략 1 kHz ≈ 4 MB, 26.6 kHz ≈ 112 MB 입니다.

주파수 분석(FFT)이 목적이라면 26.6 kHz 를 고르십시오. 더 낮은 설정은 펌웨어가 저역통과 필터 없이 샘플을 솎아내는 방식이라, 높은 주파수 성분이 낮은 주파수 자리로 접혀 들어옵니다(에일리어싱).

RMS·피크 같은 전체 진동량만 보신다면 낮은 레이트도 괜찮습니다. 자세한 내용은 SHT 진동센서 수집 도움말 5장에 있습니다.

데이터 읽기 방식

선택설명
인터럽트 (기본·권장) 센서가 알려줄 때 읽습니다. 26.6 kHz 전 속도가 나옵니다. 입고 검사(boardcheck)에서 INT1 이 PASS 인 보드에서 쓰십시오.
폴링 주기적으로 읽습니다. INT1 배선에 문제가 있을 때의 대안입니다.

측정 범위 (풀스케일)

범위분해능쓰는 경우
±2 g0.061 mg미세 진동
±4 g0.122 mg일반 (기본)
±8 g0.244 mg강한 진동
±16 g0.488 mg충격·낙하
범위를 넘는 진동은 잘려서 기록됩니다(클리핑). 수집한 CSV 의 _raw 값이 ±32767 에 붙어 있으면 범위를 키워 다시 측정하십시오. 반대로 너무 크게 잡으면 미세 진동의 분해능이 떨어집니다. 측정 단위 환산은 수집기가 자동으로 합니다 — 범위 값이 데이터에 함께 실려 가기 때문입니다.

비밀번호 기억

WiFi 비밀번호 입력란 오른쪽의 체크 상자입니다 (USB 직결에서는 비활성). 체크하면 WiFi 비밀번호를 이 PC 에 저장합니다(권한 0600). 체크를 해제하면 이미 저장돼 있던 비밀번호도 지웁니다. 여러 센서를 연속으로 설정할 때만 켜고, 끝나면 끄시는 것을 권합니다.

6. 제대로 됐는지 확인

주입 직후 — 로그에서

보여야 하는 것뜻
자격증명 출처: NVS (설정툴 주입값) ✅ 보드가 주입한 WiFi 를 쓰고 있다는 뜻 (WiFi 모드만 — USB 직결이면 확인 불가 · WiFi: skipped_serial_mode 가 정상)
펌웨어가 읽은 설정: 서버 … rate=… transport=… fs=… 보드가 되울린 값. 입력값과 같아야 합니다.
스트리밍: 시작됨 ✅데이터를 보내기 시작했다
자격증명 출처: Kconfig — 개발 빌드, NVS 무시 ❌ 가 보이면 번들 펌웨어가 개발용입니다. 이 펌웨어는 이 프로그램에서 입력한 WiFi 를 무시합니다. 배포 담당자에게 정상 패키지를 요청하십시오. (도구가 굽기 전에 막지만, 다른 경로로 구운 보드라면 이 메시지로 드러납니다)

설정 불일치 대화상자에 어느 항목이 다른지 나옵니다. 케이블을 확인하고 ② 설정 주입을 다시 실행하십시오.

7. 문제가 생기면

증상확인할 것
목록이 비어 있다 충전 전용 USB 케이블인 경우가 대부분입니다. 데이터 전송용으로 바꾸고 목록만 갱신을 누르세요.
MAC 이 읽기 실패 USB 가 멈춘 경우는 도구가 이미 자동 복구를 시도했습니다. 그래도 실패했다면 케이블을 뽑았다 꽂고 MAC 주소 확인 을 다시 누르세요. 계속 같은 구멍에서만 실패하면 케이블이나 USB 구멍을 바꿔 보세요. 원인은 아래 로그에 나옵니다.
포트 사용 중 다른 프로그램이 그 포트를 쓰고 있습니다. 수집기나 시리얼 모니터를 닫으세요.
굽는 중 멈춘다 라즈베리파이에서 흔한 USB 증상입니다. 도구가 장치를 리셋하고 한 번 더 시도할지 묻습니다 — 예를 누르세요.
./run.sh 가 “허가 거부” USB 메모리로 복사하면서 실행권한이 사라진 것입니다. bash run.sh 로 실행하세요.
아이콘을 더블클릭하면 “처음 한 번은 USB 권한 설정이 필요합니다” 권한 설정은 비밀번호 입력이 필요해 아이콘으로는 할 수 없습니다. 창에 나온 폴더에서 터미널로 bash run.sh 를 한 번 실행하세요.
아이콘을 더블클릭해도 아무 반응이 없다 패키지 폴더를 옮겼거나 지웠을 수 있습니다. 지금 쓰는 폴더에서 bash run.sh 를 한 번 실행하면 아이콘이 다시 만들어집니다.
“실행 환경에 문제가 있어 시작할 수 없습니다” 터미널에서 bash run.sh 를 실행하면 ❌ 로 원인이 표시됩니다. tkinter 가 없어 는 Lite 이미지라 GUI 를 쓸 수 없다는 뜻이고, 패키지에서 불러오지 못했습니다 는 패키지 손상입니다 — tar.gz 를 다시 푸세요.
권한 오류 패키지 폴더에서 터미널로 bash run.sh 를 다시 실행하면 빠진 권한을 설정합니다. SSH 로 접속해 쓰는 경우에만 그 뒤 다시 접속하십시오. bash install.sh --check 로 무엇이 빠졌는지 볼 수 있습니다.
주입은 됐는데 데이터가 안 온다 전송 방식과 받는 방법이 맞는지 보세요. USB 직결이면 SHT 진동센서 수집에서 센서 칸의 수신이 설정과 같은지(USB / WiFi) 보세요. WiFi 면 라즈베리파이 IP 와 수신 포트도 확인하세요.
WiFi 2대인데 유실이 크다 두 센서의 수신 포트가 같은지 확인하세요 → 4장
창이 닫히지 않는다 Esc 또는 Ctrl+Q

로그 저장 버튼으로 화면 로그를 파일로 남길 수 있습니다. 문의할 때 함께 보내 주시면 원인을 빨리 찾을 수 있습니다.
