# IIS3DWB 수신기 (라즈베리파이)

ESP32-S3가 보내는 진동 센서 데이터를 라즈베리파이에서 수신·저장합니다.
전송 경로는 디바이스 NVS 의 `transport` 값으로 **배타 선택**됩니다.

| transport | 경로 | 수신 스크립트 | 실행 |
|-----------|------|--------------|------|
| `0` | WiFi UDP | `udp_receiver.py` | `./run.sh` |
| `2` | USB 시리얼 직결 | `serial_receiver.py` | `./run.sh serial` |

> **WiFi(UDP) 구조:** 센서는 USB로 전력만 받고, 부팅 시 자동으로 NVS에 저장된
> `server_ip:server_port` 로 진동 데이터를 UDP 전송합니다. 라즈베리파이는 같은
> 네트워크에서 그 포트를 열고 수신·기록합니다.
>
> **USB 직결 구조:** WiFi 없이 USB 케이블 한 개로 데이터까지 받습니다. 센서는
> 부팅 약 3초 뒤부터 `/dev/ttyACM0` 으로 **단방향 무조건 송신**합니다
> (수신기가 없어도 계속 보냅니다).

## 빠른 시작

```bash
# 최초 1회 — 수신에 필요한 것만 설치 (ESP-IDF 불필요, 약 1분)
../setup-rpi.sh --receiver-only

./run.sh            # WiFi(UDP) 수신
./run.sh serial     # USB 직결 수신
```

## 1. 라즈베리파이에서 설치 (git clone)

```bash
git clone https://github.com/JamesjinKim/3dbw.git
cd 3dbw/rpi-receiver
chmod +x run.sh        # 최초 1회
```

추가 설치 불필요 — Python 3.6+ 표준 라이브러리만 사용합니다.

## 2. 수신기 실행

```bash
./run.sh                 # 포트 9000, vibration.csv 에 저장
./run.sh --fs 4          # 센서 풀스케일 ±4g (mg 환산용, 펌웨어와 일치)
PORT=9001 ./run.sh       # 포트 변경
```

실행하면 **이 라즈베리파이의 IP**가 표시됩니다:

```
====================================================
  IIS3DWB UDP 수신기
====================================================
  이 라즈베리파이 IP : 192.168.0.37
  수신 포트          : 9000

  ▶ 디바이스(ESP32) NVS 에 아래 값을 넣으세요:
      server_ip   = 192.168.0.37
      server_port = 9000
====================================================
  저장 파일 : vibration.csv  (raw + mg 전체 샘플)
  풀스케일  : ±4g  (감도 0.122 mg/LSB)
[수신 대기] … 센서를 흔들면 X/Y/Z 값이 변합니다. (Ctrl+C 종료)
```

## 3. 디바이스(ESP32)에 이 IP를 주입

위에서 표시된 `server_ip` / `server_port` 를 디바이스 NVS에 저장합니다.
(설정 툴 또는 NVS 직접 주입 — 펌웨어 `config_manager` 의 `srv_ip`/`srv_port`/`stream_rate`)

| NVS 키 | 값 | 설명 |
|--------|-----|------|
| `srv_ip` | 192.168.0.37 | 라즈베리파이 IP (위에서 확인) |
| `srv_port` | 9000 | 수신 포트 |
| `stream_rate` | 0 | 샘플레이트 단계 (0=1kHz) |
| `transport` | 0 | 0=UDP |

> ⚠️ 라즈베리파이 IP가 바뀌면 다시 주입해야 합니다.
> 라우터에서 **DHCP 고정 할당**으로 IP를 고정해두는 것을 권장합니다.

## 4. 검증 (1kHz 수신 확인)

디바이스에 전원(USB)을 넣으면 자동으로 WiFi 연결 → 스트리밍을 시작합니다.
수신기 화면에 1초마다 다음이 출력되면 정상 (X/Y/Z는 실제 센서값, mg):

```
[192.168.0.225] 1000Hz 유실0.00% │ X=  +12.3 Y=   -8.7 Z= +1001.4 mg │ 샘플=10000
```

> 센서를 가만히 두면 한 축(Z)이 중력 ≈ **1000 mg(1g)** 근처로 나옵니다.
> 센서를 **흔들거나 두드리면 X/Y/Z 값이 출렁이는 것**이 화면에 즉시 보입니다.

**검증 통과 기준 (rate_step=0, 1kHz):**
- ✅ 순간 레이트 ≈ **1000 Hz** (목표와 일치)
- ✅ 유실 ≈ **0%** (UDP라 약간의 유실은 정상, 1% 미만 권장)
- ✅ 정지 시 한 축이 **±1000 mg(중력)** 근처, 움직이면 값 변동
- ✅ `vibration.csv` 에 `x,y,z` 값이 정상 범위로 기록됨

종료(Ctrl+C) 시 총 패킷/샘플/평균 레이트 요약이 출력됩니다.

## 동작 요약
- UDP 포트(기본 9000)로 수신 대기
- 패킷 헤더 검증(magic "IIS3") 후 샘플 파싱
- 1초마다 화면에 **순간 레이트 / 유실률 / 최신 X·Y·Z 값(mg)** 표시
- CSV로 전체 샘플 저장 (raw LSB + mg 가속도)

### CSV 컬럼 (`vibration.csv`)

| 컬럼 | 설명 |
|------|------|
| `recv_iso` | 라즈베리파이 수신 시각 (ms 정밀도) |
| `seq` | 패킷 시퀀스 번호 (유실 추적용) |
| `timestamp_ms` | 디바이스 부팅 후 경과 ms (패킷 생성 시각) |
| `sample_idx` | 패킷 내 샘플 순번 (0~199) |
| `x_raw, y_raw, z_raw` | 원시 가속도 (int16 LSB) |
| `x_mg, y_mg, z_mg` | mg 단위 가속도 (감도 환산, 풀스케일 의존) |

> 후처리(FFT, RMS 등)는 `x_mg/y_mg/z_mg` 를, 정밀 분석은 `x_raw` 등을 사용하세요.

## 샘플레이트 단계 (rate_step)

| rate_step | 샘플레이트 | 비고 |
|-----------|-----------|------|
| 0 | 1 kHz | 기본, **1단계 검증 대상** |
| 1 | 3.3 kHz | |
| 2 | 6.6 kHz | 고속 (FIFO 읽기 필요, 2단계) |
| 3 | 13.3 kHz | 고속 (2단계) |
| 4 | 26.6 kHz | 최대 (2단계) |

> 현재 펌웨어 1단계는 **폴링 방식**이라 1kHz까지 안정적입니다.
> 3.3kHz 이상은 FIFO 묶음 읽기(2단계) 구현 후 검증 예정.

## 패킷 포맷
펌웨어 `components/sensor_streamer/sensor_streamer.h` 와 일치. 파서는
`iis3dwb_packet.py` 한 곳에만 있고 UDP·시리얼 수신기가 공용으로 씁니다.

```
v1 헤더 16B: magic(4,"IIS3") ver(1) rate_step(1) sample_count(2) seq(4) timestamp_ms(4)
v2 헤더 18B: v1 + full_scale_g(1) reserved(1)          ← 현재 펌웨어
페이로드   : sample_count × {int16 x, int16 y, int16 z}  (little-endian)
패킷 크기  : 18 + 200×6 = 1218 B
```

- **헤더 크기는 `ver` 로 판별해야 합니다.** v2 는 v1 뒤에 2바이트를 덧붙인
  구조라 앞 16바이트가 동일합니다. v2 패킷을 16B 헤더로 파싱하면 샘플
  오프셋이 2바이트 밀려 **X/Y/Z 축이 한 칸씩 어긋난 채 조용히 기록됩니다**
  (길이 검사도 통과하므로 오류가 드러나지 않습니다).

  실기기 v2 패킷(seq=377, 200샘플)으로 두 파서를 비교한 결과:

  | | X | Y | Z | 중력 축 |
  |---|---|---|---|---|
  | 올바른 파싱 (18B) | +35.9 | −110.7 | **+1059.3** | Z ✅ |
  | 잘못된 파싱 (16B) | **+1054.2** | +35.9 | −110.7 | X ❌ |

  첫 샘플은 `x = full_scale_g` 바이트가 섞여 `(4, 309, -881)` 같은 값이 됩니다.

> ⚠️ **합성 가속도 검사로는 이 버그를 잡을 수 없습니다.**
> 축이 한 칸 밀려도 값의 집합이 거의 보존되므로 √(x²+y²+z²) 는
> 1065.8 mg vs 1061.2 mg (차이 4.6 mg)로 사실상 동일합니다. 설계문서 7.3.1 이
> 권하는 '중력 1g 확인'은 감도 환산 검증에는 유효하지만 헤더 정렬 오류는
> 통과시킵니다. **정지 상태에서 중력이 어느 축에 실리는지**를 함께 봐야 합니다.
- v2 는 헤더에 풀스케일이 들어 있어 `--fs` 없이 mg 환산이 정확합니다.
  `--fs` 는 구형 v1 펌웨어용 폴백입니다.
- seq로 패킷 손실/유실률 측정 (32비트 랩어라운드 처리)

## USB 직결(시리얼) 수신

```bash
./run.sh serial                          # 포트 자동 감지 (/dev/ttyACM*)
python3 serial_receiver.py --port /dev/ttyACM0
python3 serial_receiver.py --seconds 60  # 60초만 측정하고 종료
python3 serial_receiver.py --no-csv      # 화면 표시만 (고속에서 디스크 부하 회피)
```

필요 패키지: `pyserial` (`sudo apt install -y python3-serial`)

### 고속(26.6 kHz)에서의 디스크 용량

라즈베리파이 4에서 측정한 수신기 처리 능력은 약 **16만 샘플/초**로, 최고 속도
26.6 kHz(2.66만 샘플/초)의 약 6배 여유가 있습니다. **CPU 는 병목이 아닙니다.**

병목은 **디스크 용량**입니다. CSV 한 줄이 약 65 바이트이므로:

| 샘플레이트 | CSV 증가 속도 | 1시간 | 비고 |
|-----------|--------------|-------|------|
| 1 kHz | 0.065 MB/s | 0.23 GB | |
| 3.3 kHz | 0.21 MB/s | 0.77 GB | 기본 |
| 26.6 kHz | 1.7 MB/s | **6.2 GB** | 최대 |

장시간 고속 측정 시:
- `--seconds 60` 으로 측정 구간을 제한하거나
- `--no-csv` 로 화면 표시만 하거나 (유실률·레이트 검증 목적)
- 외장 SSD/USB 디스크에 저장하세요 (`--out /mnt/ssd/vib.csv`).
  SD 카드에 초당 1.7 MB 를 장시간 쓰는 것은 카드 수명에도 좋지 않습니다.

`df -h .` 로 남은 용량을 먼저 확인하는 습관을 권합니다.

**동작 특성 (설계문서 7.5 / 7.6):**
- 스트림 선두에 부팅 로그가 섞일 수 있어 magic("IIS3") 스캔으로 경계를 찾습니다.
  수신기가 자동 재동기하며, 버린 바이트 수를 종료 시 `재동기폐기` 로 보고합니다.
- 디바이스는 단방향 송신이라 수신을 멈춰도 송신은 계속됩니다. 재개 시
  `reset_input_buffer()` 로 묵은 데이터를 비우고 시작합니다 (스크립트가 자동 처리).
- `idf.py monitor` 와 **동시 사용 불가** — 같은 포트를 두 프로그램이 열 수 없습니다.

**주의:** 시리얼 모드에서는 펌웨어가 스트리밍 중 로그를 차단합니다(데이터 전용 채널).
따라서 `idf.py monitor` 로는 사람이 읽을 로그가 보이지 않는 것이 정상입니다.

## 문제 해결

| 증상 | 확인 |
|------|------|
| 아무것도 안 들어옴 | 디바이스/라즈베리파이가 **같은 네트워크(2.4GHz)** 인지, NVS의 `srv_ip`가 위 표시된 IP와 같은지 |
| 방화벽 | `sudo ufw allow 9000/udp` (ufw 사용 시) |
| 디바이스 WiFi 미연결 | 디바이스 시리얼 로그에서 WiFi 연결 성공 여부 확인 |
| 레이트가 1000Hz 미만 | 네트워크 혼잡 또는 WiFi 신호 약함 — 디바이스를 라우터 근처로 |
| (시리얼) 포트 없음 | `ls /dev/ttyACM*` 확인. 데이터용 USB 케이블인지, `dmesg \| tail` 로 인식 여부 |
| (시리얼) 권한 거부 | `sudo usermod -aG dialout $USER` 후 재로그인 |
| (시리얼) 데이터 안 옴 | NVS `transport` 가 **2** 인지 확인 (0이면 WiFi 로 나감) |
| (시리얼) 포트 사용 중 | `idf.py monitor` 등 다른 프로그램이 포트를 점유 중인지 확인 |
| X/Y/Z 가 이상한 값 | 구형 수신기로 v2 패킷을 파싱했을 때의 증상. 이 폴더의 최신 스크립트를 사용 |
