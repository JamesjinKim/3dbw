1. 시작하기 전에

진동센서 1대에 포토센서 1개

진동센서마다 자기 포토센서가 짝을 이룹니다. 각 짝은 서로 완전히 독립적으로 동작합니다 — A가 수집 중이어도 B는 대기 상태일 수 있고, 두 대가 겹쳐 수집할 수도 있습니다. 

진동센서 A ── 포토센서 A(DIN1) 감지 → A만 정해진 시간 수집 → A 저장 → A 대기
진동센서 B ── 포토센서 B(DIN2) 감지 → B만 정해진 시간 수집 → B 저장 → B 대기

고정 장치 이름 — 어느 센서인지 헷갈리지 않게

같은 종류의 진동센서 두 대는 소프트웨어로 구분할 방법이 없습니다. USB 브리지칩에 고유 일련번호가 없고, 데이터 자체에도 장비 식별자가 없기 때문입니다. 남는 근거는 어느 USB 구멍에 꽂혔는가 하나뿐입니다.

그런데 리눅스가 붙이는 /dev/ttyACM0, /dev/ttyACM1 번호는 꽂는 순서와 재부팅에 따라 바뀝니다. 그래서 이 프로그램은 USB 구멍마다 변하지 않는 이름을 만들어 씁니다. 윈도우에서 “이 장치는 항상 COM3” 으로 고정해 두는 것과 같은 개념입니다. 

/dev/iis3dwb1   →  1번 구멍에 꽂힌 센서 (항상)
/dev/iis3dwb2   →  2번 구멍에 꽂힌 센서 (항상)

처음 한 번만 하면 됩니다

# 1) 센서를 모두 꽂은 상태에서 번호를 자동 지정
python3 slots.py --auto

# 2) 고정 이름을 만든다 (관리자 권한 필요, 한 번만)
sudo python3 slots.py --make-udev

# 3) 확인
python3 slots.py

확인하면 이렇게 나옵니다.

이름   고정 장치 이름        현재 장치       USB 포트     포토센서
1      /dev/iis3dwb1      /dev/ttyACM0   usb-0:1.2    DIN1
2      /dev/iis3dwb2      /dev/ttyACM1   usb-0:1.3    DIN2

재부팅해도, 케이블을 뽑았다 꽂아도 고정 이름은 그대로입니다. 현재 장치 쪽 번호는 바뀔 수 있지만 상관없습니다.

어느 구멍이 몇 번인지 잊었다면 아무 때나 확인할 수 있습니다. 포트에 스티커를 붙일 필요가 없습니다. 
ls -l /dev/iis3dwb*
케이블을 다른 구멍으로 옮기면 번호가 바뀝니다. 고정되는 것은 “센서”가 아니라 “구멍”이기 때문입니다. 센서를 교체할 때는 같은 구멍에 꽂으세요. 구성을 바꿨다면 위 1~2단계를 다시 실행하면 됩니다.

포토센서 활성 레벨

아무 입력이 없을 때 DIN 핀은 HIGH로 읽힙니다. 산업용 포토센서는 대개 NPN 출력이라 감지되면 신호를 GND로 끌어내리므로 활성 레벨은 LOW가 기본입니다. PNP 출력이면 반대로 설정하세요.

화면의 현재 레벨 표시를 보면 바로 확인됩니다. 아무것도 가리지 않았는데 ‘감지’로 보인다면 활성 레벨이 반대입니다.

4. 데이터 단위 — 스케일은 이미 적용돼 있습니다

결론 먼저. CSV의 _mg 열은 이미 환산이 끝난 값입니다. 별도의 스케일 연산이 필요 없습니다. 그대로 쓰시면 됩니다.

CSV 열 설명

recv_iso,seq,timestamp_ms,sample_idx,x_raw,y_raw,z_raw,x_mg,y_mg,z_mg
2026-09-23T12:55:17.996,6,4200,0,-571,-412,8001,-69.66,-50.26,976.12
열뜻
recv_iso기록 시각
seq패킷 순번. 건너뛰면 그 구간이 유실된 것입니다.
timestamp_ms센서 부팅 후 경과 시간(ms). 지터가 없어 시간축으로 쓰기 좋습니다.
sample_idx그 패킷 안에서의 순번 (0~199)
x_raw, y_raw, z_raw센서 원시값 (16비트 정수, 단위 LSB)
x_mg, y_mg, z_mg 환산된 가속도 (mg). 분석에는 이 열을 쓰세요.

환산이 어떻게 되는가

스케일을 정하는 것은 측정 범위(±2/4/8/16 g)이지 샘플레이트가 아닙니다. 범위 값은 데이터 패킷 안에 함께 실려 오므로 수집기가 자동으로 맞는 감도를 적용합니다. 설정툴에서 ±8g를 ±4g로 바꾸셔도 사용자가 할 일은 없습니다.

측정 범위감도검증 (실기기)
±2 g0.061 mg/LSB
±4 g0.122 mg/LSB8001 × 0.122 = 976.12 ✓
±8 g0.244 mg/LSB4029 × 0.244 = 983.08 ✓
±16 g0.488 mg/LSB

실기기 데이터 50,000행 × 3축을 전수 대조한 결과 불일치 0건이었습니다.

원시값을 직접 쓰실 때

mg    = raw × 감도                 (위 표)
g     = mg / 1000
m/s²  = g × 9.80665
측정 범위를 넘는 진동은 잘려서 기록됩니다(클리핑). _raw 값이 ±32767에 붙어 있다면 범위를 키워 다시 측정하세요. 반대로 범위가 너무 크면 미세 진동의 분해능이 떨어집니다.

5. 샘플레이트 선택 — 꼭 읽어 주세요

주파수 분석(FFT)이 목적이라면 26.6 kHz로 수집하세요. 그보다 낮은 설정은 실제로 존재하지 않는 저주파 성분을 만들어 냅니다.

왜 그런가

이 센서는 출력 속도가 26.667 kHz로 하드웨어 고정입니다. 1 kHz나 3.3 kHz를 고르면 센서가 느리게 도는 것이 아니라, 펌웨어가 N개 중 1개만 골라내는 방식입니다. 

26.6 kHz 선택 →  ●●●●●●●●●●●●●●●●   전부 사용
 3.3 kHz 선택 →  ●・・・・・・・●・・・・・・・   8개 중 1개만 사용 (저역통과 필터 없음)

신호를 솎아내기 전에 저역통과 필터를 거치지 않기 때문에, 새 나이퀴스트 주파수를 넘는 성분이 사라지지 않고 낮은 주파수 자리로 접혀 들어옵니다. 이것을 에일리어싱(aliasing)이라고 합니다.

접힌 뒤 나타나는 자리는 다음 식으로 계산됩니다. 실제 진동 주파수를 f, 고른 샘플레이트를 fs라 할 때 

기록되는 주파수 = | f − (f / fs 를 반올림한 정수) × fs |

검증 — 이 주장의 근거

아래는 모두 실기기에서 수집한 데이터로 확인한 결과입니다. 판단에 중요한 내용이라 근거를 그대로 싣습니다.

① 같은 데이터를 두 방식으로 솎아 비교
26.6 kHz로 12초 수집한 실제 데이터(Z축)를 소프트웨어로 1/8 솎았습니다. 기준은 원본 스펙트럼의 0~1.67 kHz 구간입니다.

방식0~1.67 kHz 파워기준 대비
기준 (원본의 해당 대역)40.11 mg²1.00배
펌웨어 방식 (그냥 솎기)164.06 mg² 4.09배
올바른 방식 (필터 후 솎기)39.67 mg²0.99배

주파수 구간별로 보면 100~1666 Hz에서 약 10배(+10 dB) 부풀려집니다. 올바른 방식은 기준과 거의 정확히 일치합니다.

② 접힌 주파수가 예측과 맞는가
실제 수집 데이터에서 3.8~4.2 kHz 대역만 남기고(합성 신호 없이) 솎아 보았습니다.

실제 진동기록된 주파수예측
4,017 Hz (실측 피크)682 Hz667 Hz일치
4,000 Hz (기준 신호)667 Hz667 Hz일치
8,000 Hz (기준 신호)1,333 Hz1,333 Hz일치
12,000 Hz (기준 신호)1,334 Hz1,334 Hz일치

올바른 방식(필터 후 솎기)에서는 같은 신호가 50 mg → 0.017 mg로 제거되어 나타나지 않습니다.

③ 눈으로 보기

실제 센서 데이터에 4 kHz 진동 50 mg을 더한 것입니다. 왼쪽(26.6 kHz)에서는 4 kHz에 제대로 보이지만, 오른쪽에서 펌웨어 방식(빨강)은 667 Hz에 실재하지 않는 봉우리를 만들고 바닥 잡음도 약 10배 높습니다. 올바른 방식(초록)에는 그 봉우리가 없습니다.

정직하게 덧붙입니다. 얼마나 심한지는 측정 대상이 어떤 주파수로 진동하는지에 달려 있습니다. 나이퀴스트 위에 에너지가 거의 없는 기계라면 영향이 작습니다. 다만 필터가 없다는 사실 자체는 코드로 확인된 것이라, 높은 주파수 성분이 있으면 반드시 접혀 들어옵니다. 정지 상태의 이 센서에서도 전체 에너지의 75.5%가 1.67 kHz 위에 있었습니다.

어떤 설정을 고를까

26.6 kHz13.3 kHz 정확 ✅정확
13.3 kHz6.67 kHz경계 — 주의정확
6.6 kHz3.3 kHz접힘 발생 ⚠정확

RMS·피크 같은 전체 진동량만 보신다면 낮은 레이트도 괜찮습니다. 위 실측에서 보듯 총 에너지는 보존되기 때문입니다. 문제가 되는 것은 “몇 Hz에서 진동하는가”를 따질 때입니다.

권장 방법

항상 26.6 kHz로 수집하고, 분석 단계에서 필요한 대역만 추출하십시오. 용량이 부담되면 바이너리 형식을 쓰면 1/11.6로 줄어듭니다. 

# 올바른 다운샘플링 — 필터를 먼저 거칩니다
from scipy.signal import decimate
z_3k = decimate(z_mg, 8, ftype='fir', zero_phase=True)   # 26.6kHz → 3.3kHz

6. 분석 예시

먼저 데이터가 온전한지 확인

import json
m = json.load(open("run_0012.json"))
assert m["loss_pct"] == 0,    "유실이 있습니다"
assert m["queue_drops"] == 0, "기록이 밀렸습니다"
assert m["shortfall"] is None, m["shortfall"]
print(m["rate_hz"], "Hz,  ±", m["full_scale_g"], "g", sep="")

진동 크기 (RMS·피크)

import numpy as np
d  = np.loadtxt("run_0012.csv", delimiter=",", skiprows=1, usecols=(7,8,9))
ac = d - d.mean(axis=0)                    # 중력(DC) 성분 제거
rms  = np.sqrt((ac**2).mean(axis=0))       # 축별 RMS [mg]
peak = np.abs(ac).max(axis=0)              # 축별 피크 [mg]
print("RMS  X %.1f  Y %.1f  Z %.1f mg" % tuple(rms))
print("Peak X %.1f  Y %.1f  Z %.1f mg" % tuple(peak))

중력은 항상 약 1000 mg의 DC 성분으로 들어 있습니다. 진동만 보려면 위처럼 평균을 빼세요.

주파수 스펙트럼 (26.6 kHz 수집분에서만)

fs = m["rate_hz"]                          # json 에서 읽는다
z  = ac[:, 2]                              # Z축
n  = len(z)
spec = np.abs(np.fft.rfft(z * np.hanning(n))) * 2 / n
freq = np.fft.rfftfreq(n, 1/fs)
top = freq[np.argsort(spec)[-5:]][::-1]
print("주요 주파수:", np.round(top, 1), "Hz")
